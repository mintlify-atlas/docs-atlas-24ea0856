dstack orchestrates GPU workloads using YAML configuration files applied with `dstack apply`. This guide walks you through creating a fleet to provide compute, then submitting each type of run: a dev environment for interactive development, a task for batch jobs, and a service for model deployment.

<Note>
  Before starting, make sure you have [installed the dstack server and CLI](/installation) and configured at least one backend or have on-prem servers accessible over SSH.
</Note>

## Create a fleet

A fleet is a pool of compute instances that dstack uses to run your workloads. You must create a fleet before submitting any runs. dstack supports two fleet types depending on your infrastructure.

<Tabs>
  <Tab title="Backend fleet">
    If you have configured a cloud or Kubernetes [backend](/concepts/backends), create a fleet by defining a `fleet.dstack.yml` file:

    ```yaml fleet.dstack.yml
    type: fleet
    name: default

    # Allow provisioning of up to 2 instances
    nodes: 0..2

    # Deprovision instances above the minimum after they remain idle
    idle_duration: 1h

    resources:
      # Allow provisioning up to 8 GPUs per instance
      gpu: 0..8
    ```

    Apply the configuration with `dstack apply`:

    ```bash
    dstack apply -f fleet.dstack.yml
    ```

    ```
      #  BACKEND  REGION           RESOURCES                 SPOT  PRICE
      1  gcp      us-west4         2xCPU, 8GB, 100GB (disk)  yes   $0.010052
      2  azure    westeurope       2xCPU, 8GB, 100GB (disk)  yes   $0.0132
      3  gcp      europe-central2  2xCPU, 8GB, 100GB (disk)  yes   $0.013248

    Create the fleet? [y/n]: y

      FLEET    INSTANCE  BACKEND  RESOURCES  PRICE  STATUS  CREATED
      default  -         -        -          -      -       10:36
    ```

    When `nodes` starts at `0`, `dstack apply` registers the fleet as a template. Instances are provisioned on demand when you submit a run. If you need a multi-node cluster, set the [`placement`](/concepts/fleets#cluster-placement) property to `cluster`.
  </Tab>
  <Tab title="SSH fleet">
    If you have on-prem servers accessible over SSH, create an SSH fleet without any backend configuration. Define a `fleet.dstack.yml` file with your host details:

    ```yaml fleet.dstack.yml
    type: fleet
    name: my-fleet

    ssh_config:
      user: ubuntu
      identity_file: ~/.ssh/id_rsa
      hosts:
        - 3.255.177.51
        - 3.255.177.52
    ```

    Apply the configuration with `dstack apply`:

    ```bash
    dstack apply -f fleet.dstack.yml
    ```

    ```
    Provisioning...
    ---> 100%

      FLEET     INSTANCE  GPU             PRICE  STATUS  CREATED
      my-fleet  0         L4:24GB (spot)  $0     idle    3 mins ago
                1         L4:24GB (spot)  $0     idle    3 mins ago
    ```

    <Note>
      SSH fleet hosts must have Docker and GPU drivers installed. See [SSH fleet requirements](/concepts/fleets#ssh-fleets) for the full list of prerequisites.
    </Note>

    For multi-node cluster placement, set the [`placement`](/concepts/fleets#ssh-placement) property to `cluster`.
  </Tab>
</Tabs>

## Submit your first run

dstack supports three run types. Each is defined in a YAML configuration file and submitted with `dstack apply`.

<Tabs>
  <Tab title="Dev environment">
    A [dev environment](/concepts/dev-environments) provisions an instance and connects it to your desktop IDE over SSH. It is useful for interactive experimentation and debugging.

    Create a `.dstack.yml` configuration file:

    ```yaml .dstack.yml
    type: dev-environment
    name: vscode

    # If `image` is not specified, dstack uses its default image
    python: "3.11"
    #image: dstackai/base:py3.13-0.7-cuda-12.1

    ide: vscode

    # Uncomment to request GPU resources
    #resources:
    #  gpu: 24GB
    ```

    Submit the run:

    ```bash
    dstack apply -f .dstack.yml
    ```

    ```
     #  BACKEND  REGION           RESOURCES                 SPOT  PRICE
     1  gcp      us-west4         2xCPU, 8GB, 100GB (disk)  yes   $0.010052
     2  azure    westeurope       2xCPU, 8GB, 100GB (disk)  yes   $0.0132
     3  gcp      europe-central2  2xCPU, 8GB, 100GB (disk)  yes   $0.013248

    Submit the run vscode? [y/n]: y

    Launching `vscode`...
    ---> 100%

    To open in VS Code Desktop, use this link:
      vscode://vscode-remote/ssh-remote+vscode/workflow
    ```

    Click the printed link to open the environment in VS Code Desktop. You can also connect directly with `ssh vscode`.
  </Tab>
  <Tab title="Task">
    A [task](/concepts/tasks) schedules a batch job or runs a web app on provisioned compute. Tasks can forward ports to your local machine and can run as distributed multi-node jobs.

    Create a `task.dstack.yml` configuration file:

    ```yaml task.dstack.yml
    type: task
    name: streamlit

    # If `image` is not specified, dstack uses its default image
    python: "3.11"
    #image: dstackai/base:py3.13-0.7-cuda-12.1

    # Commands to run
    commands:
      - pip install streamlit
      - streamlit hello
    # Ports to forward to localhost
    ports:
      - 8501

    # Uncomment to request GPU resources
    #resources:
    #  gpu: 24GB
    ```

    Submit the run:

    ```bash
    dstack apply -f task.dstack.yml
    ```

    ```
     #  BACKEND  REGION           RESOURCES                 SPOT  PRICE
     1  gcp      us-west4         2xCPU, 8GB, 100GB (disk)  yes   $0.010052
     2  azure    westeurope       2xCPU, 8GB, 100GB (disk)  yes   $0.0132
     3  gcp      europe-central2  2xCPU, 8GB, 100GB (disk)  yes   $0.013248

    Submit the run streamlit? [y/n]: y

    Provisioning `streamlit`...
    ---> 100%

      Welcome to Streamlit. Check out our demo in your browser.

      Local URL: http://localhost:8501
    ```

    Ports listed in `ports` are automatically forwarded to `localhost` while the task is running. To run a distributed task across multiple nodes, add a [`nodes`](/concepts/tasks#distributed-tasks) field.
  </Tab>
  <Tab title="Service">
    A [service](/concepts/services) deploys a model or web app as a public endpoint. It supports auto-scaling, rate limiting, and custom domains via a [gateway](/concepts/gateways).

    Create a `service.dstack.yml` configuration file:

    ```yaml service.dstack.yml
    type: service
    name: qwen36-service

    image: lmsysorg/sglang:v0.5.10.post1

    commands:
      - |
        sglang serve \
          --model-path Qwen/Qwen3.6-27B \
          --host 0.0.0.0 \
          --port 30000 \
          --reasoning-parser qwen3
    # Expose the SGLang server port
    port: 30000

    # Specify the model name for OpenAI-compatible routing
    model: Qwen/Qwen3.6-27B

    # Required resources
    resources:
      gpu: H100
    ```

    Submit the run:

    ```bash
    dstack apply -f service.dstack.yml
    ```

    ```
     #  BACKEND  REGION     INSTANCE              RESOURCES                          SPOT  PRICE
     1  nebius   eu-north1  gpu-h100-sxm          16xCPU, 250GB, 1xH100 (80GB)      no    $2.95
     2  runpod   US-CA-2    NVIDIA H100 80GB HBM3 64xCPU, 1004GB, 1xH100 (80GB)     no    $2.99

    Submit the run qwen36-service? [y/n]: y

    Provisioning `qwen36-service`...
    ---> 100%

    Service is published at:
      http://localhost:3000/proxy/services/main/qwen36-service/
    Model Qwen/Qwen3.6-27B is published at:
      http://localhost:3000/proxy/models/main/
    ```

    <Note>
      To enable auto-scaling, rate limits, or a custom domain with HTTPS, configure a [gateway](/concepts/gateways) before deploying the service.
    </Note>
  </Tab>
</Tabs>
