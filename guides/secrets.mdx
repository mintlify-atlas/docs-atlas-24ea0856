---
title: "Managing Secrets for Secure Run Configurations"
description: "Create, list, retrieve, and delete project-scoped secrets in dstack, then reference them in run configurations via environment variables and registry auth."
---

Secrets give you a centralized place to store sensitive values — such as API keys, tokens, and registry passwords — so you never have to hard-code credentials in your run configurations. Secrets are scoped to a project, managed by project admins, and referenced in configurations using an interpolation syntax that keeps the actual value off disk.

<Note>
  By default, secrets are stored in plaintext in the database. To store secrets encrypted, configure [server encryption](/guides/server-deployment#encryption).
</Note>

## Managing secrets

### Create or update a secret

Use `dstack secret set` to create a new secret or update the value of an existing one:

```bash
dstack secret set my_secret some_secret_value
```

```
OK
```

To update an existing secret, run the same command with the new value:

```bash
dstack secret set my_secret another_secret_value
```

```
OK
```

### List secrets

Use `dstack secret list` (or just `dstack secret`) to see all secrets defined in the current project. Values are masked:

```bash
dstack secret
```

```
 NAME       VALUE  
 hf_token   ****** 
 my_secret  ******
```

### Retrieve a secret value

To see the plaintext value of a specific secret, use `dstack secret get`:

```bash
dstack secret get my_secret
```

```
 NAME       VALUE             
 my_secret  some_secret_value
```

### Delete a secret

Use `dstack secret delete` to remove a secret. The CLI prompts for confirmation before deleting:

```bash
dstack secret delete my_secret
```

```
Delete the secret my_secret? [y/n]: y
OK
```

## Using secrets in run configurations

Reference secrets in your `.dstack.yml` using the `${{ secrets.<secret_name> }}` syntax. Interpolation is supported in the `env` and `registry_auth` properties.

### Environment variables

To pass a sensitive environment variable — such as a Hugging Face token — to a run, first store the value as a secret:

```bash
dstack secret set hf_token {hf_token_value}
```

Then reference the secret in your configuration's `env` block:

```yaml .dstack.yml
type: service
env:
  - HF_TOKEN=${{ secrets.hf_token }}
commands:
  - ...
```

When the run starts, `dstack` resolves the secret server-side and injects the value as an environment variable. The plaintext value is never written to the configuration file.

### Registry authentication

To pull a private Docker image, store the registry password or API key as a secret and reference it in `registry_auth`:

```yaml .dstack.yml
type: service
image: nvcr.io/nim/deepseek-ai/deepseek-r1-distill-llama-8b
registry_auth:
  username: $oauthtoken
  password: ${{ secrets.ngc_api_key }}
```

First create the secret:

```bash
dstack secret set ngc_api_key {your_ngc_api_key}
```

`dstack` will resolve `${{ secrets.ngc_api_key }}` at run time and use it to authenticate against the registry before pulling the image.
