---
title: "dstack server/config.yml reference"
description: "Reference for ~/.dstack/server/config.yml. Documents projects, backend credentials for AWS, GCP, Azure and others, encryption keys, and default permissions."
---

The `~/.dstack/server/config.yml` file controls server-level settings including which cloud backends are active, encryption at rest, and default user permissions. The server reads this file on startup; changes take effect after a restart.

```yaml
# Minimal example: one project with an AWS backend
projects:
  - name: main
    backends:
      - type: aws
        regions: [us-east-1, eu-west-1]
        creds:
          type: access_key
          access_key: AKIAIOSFODNN7EXAMPLE
          secret_key: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

---

## Root fields

<ParamField body="projects" type="ProjectConfig[]" required>
  List of projects to create or update on startup. Each entry defines a project name and its associated backends. See [`projects[n]`](#projectsn).
</ParamField>

<ParamField body="encryption" type="EncryptionConfig">
  Encryption at rest configuration. When present, dstack encrypts sensitive values (credentials, tokens) stored in the database. See [`encryption`](#encryption).
</ParamField>

<ParamField body="default_permissions" type="DefaultPermissions">
  Server-wide permission defaults that control what non-admin users can do. See [`default_permissions`](#default_permissions).
</ParamField>

<ParamField body="plugins" type="string[]">
  List of server-side plugin module names to enable on startup.
</ParamField>

---

## `projects[n]`

Each entry in the `projects` array maps to one dstack project.

<ParamField body="name" type="string" required>
  The project name. Must be unique across the server.
</ParamField>

<ParamField body="backends" type="BackendConfig[]">
  List of cloud backends available to runs in this project. Each backend has a `type` discriminator field. See the per-backend sections below.
</ParamField>

---

## `projects[n].backends`

### `type: aws`

Provisions instances using Amazon Web Services.

<ParamField body="type" type="string" required>
  Must be `"aws"`.
</ParamField>

<ParamField body="regions" type="string[]">
  AWS regions to use (e.g. `[us-east-1, eu-west-1]`). When omitted, all regions are eligible.
</ParamField>

<ParamField body="creds" type="object" required>
  AWS credentials. Two variants are supported.
</ParamField>

<AccordionGroup>
  <Accordion title="creds type: access_key">
    Authenticates with a static IAM access key pair.

    <ParamField body="type" type="string" required>
      Must be `"access_key"`.
    </ParamField>

    <ParamField body="access_key" type="string" required>
      AWS access key ID.
    </ParamField>

    <ParamField body="secret_key" type="string" required>
      AWS secret access key.
    </ParamField>

    ```yaml
    creds:
      type: access_key
      access_key: AKIAIOSFODNN7EXAMPLE
      secret_key: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
    ```
  </Accordion>

  <Accordion title="creds type: default">
    Uses the AWS default credential chain (environment variables, `~/.aws/credentials`, instance profile).

    <ParamField body="type" type="string" required>
      Must be `"default"`.
    </ParamField>

    ```yaml
    creds:
      type: default
    ```
  </Accordion>
</AccordionGroup>

## `encryption`

When the `encryption` block is present, dstack encrypts sensitive fields in the database using the first key in the `keys` list. Older keys remain in the list for decryption of previously encrypted data.

<ParamField body="keys" type="EncryptionKeyConfig[]" required>
  Ordered list of encryption keys. The first key is used for encryption; all keys are tried for decryption.
</ParamField>

### Key types

<AccordionGroup>
  <Accordion title="type: aes">
    AES-256-GCM symmetric encryption.

    <ParamField body="type" type="string" required>
      Must be `"aes"`.
    </ParamField>

    <ParamField body="secret" type="string" required>
      Base64-encoded 32-byte key. Generate with `openssl rand -base64 32`.
    </ParamField>

    ```yaml
    encryption:
      keys:
        - type: aes
          secret: base64encodedkeyhere==
    ```
  </Accordion>

  <Accordion title="type: identity">
    No-op key: data is stored unencrypted. Useful for disabling encryption while retaining the config structure.

    <ParamField body="type" type="string" required>
      Must be `"identity"`.
    </ParamField>
  </Accordion>
</AccordionGroup>

## `default_permissions`

Controls what non-admin users are permitted to do across the server. All fields default to `true` except `allow_managers_manage_secrets`.

<ParamField body="allow_non_admins_create_projects" type="boolean" default="true">
  When `true`, regular users (non-global admins) can create and manage their own projects. Set to `false` to restrict project creation to global admins.
</ParamField>

<ParamField body="allow_non_admins_manage_ssh_fleets" type="boolean" default="true">
  When `true`, regular project members (role: User) can add and delete SSH fleets. Set to `false` to restrict fleet management to project managers and admins.
</ParamField>

<ParamField body="allow_managers_manage_secrets" type="boolean" default="false">
  When `true`, project managers can create, update, and delete project secrets. When `false`, only global admins can manage secrets.
</ParamField>

```yaml
default_permissions:
  allow_non_admins_create_projects: false
  allow_non_admins_manage_ssh_fleets: true
  allow_managers_manage_secrets: false
```

## Complete example

The following example configures two backends in a single project, enables AES encryption, and restricts project creation to admins.

```yaml
projects:
  - name: main
    backends:
      - type: aws
        regions: [us-east-1, eu-west-1]
        creds:
          type: access_key
          access_key: AKIAIOSFODNN7EXAMPLE
          secret_key: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
      - type: gcp
        project_id: my-gcp-project
        regions: [us-central1]
        creds:
          type: service_account
          filename: /home/user/.config/gcloud/sa.json

encryption:
  keys:
    - type: aes
      secret: base64encodedkeyhere==

default_permissions:
  allow_non_admins_create_projects: false
  allow_non_admins_manage_ssh_fleets: true
  allow_managers_manage_secrets: false
```
